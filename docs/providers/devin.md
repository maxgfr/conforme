# Devin Desktop (formerly Windsurf)

> Cognition's AI IDE, formerly Windsurf. Source: `--from devin`

Windsurf was renamed Devin Desktop in v3.0.12 (2026-06-02). Since v3.6.21
(2026-07-29) new tabs defaulted to the **Devin Local** agent, and v3.9.19
(2026-09-08) removed Cascade, Windsurf's original agent: "Devin Local is now
the only agent available in Devin Desktop". Devin Local runs on the Devin CLI
harness, so the Devin CLI documentation is what describes the files read.

conforme's tool id was `windsurf` until 4.0.0 and is now `devin`.

## Config files

| Feature | Path | Format |
|---------|------|--------|
| Rules | `.devin/rules/*.md` (also loaded: legacy `.windsurf/rules/*.md`, root `.windsurfrules`) | YAML frontmatter: `trigger`, `description`, `globs` |
| Skills | `.devin/skills/<name>/SKILL.md` (legacy `.windsurf/skills/` is still read) | YAML frontmatter: `name`, `description`, `triggers`, `allowed-tools`, … |
| MCP | `.devin/mcp_config.json` (project; `.devin/mcp_config.local.json` for local secrets) | JSON: `{ "mcpServers": { ... } }`; no `type`; remote `url` + optional `transport: http\|sse` + `headers`; `${env:VAR}` references |
| Agents | `.devin/agents/<name>.md` or `<name>/AGENT.md` (also `.agents/agents/`) | YAML frontmatter: `name`, `description`, `model`, `allowed-tools`, `max-nesting` (experimental). **Not generated by conforme** |

## Activation modes

| Mode | Frontmatter |
|------|------------|
| Always | `trigger: always_on` |
| GlobMatch | `trigger: glob` + `globs: "**/*.ts, **/*.tsx"` |
| AgentDecision | `trigger: model_decision` + `description: "..."` (`trigger: agent` means the same and is read as such) |
| Manual | `trigger: manual` |

## conforme adapter

- File: `src/adapters/devin.rs`
- ID: `devin`
- Detection: `.devin/`, `.windsurf/`, or a root `.windsurfrules`
- Capabilities: activation_modes, skills, MCP
- No agents (`sync` warns that they are skipped)
- Writes `.devin/rules/`, `.devin/skills/` and `.devin/mcp_config.json`, also for a project that still has only `.windsurf/`
- `read()` merges `.devin/rules/` and `.windsurf/rules/` (both read recursively; on a name clash the `.devin/` copy wins), adds `.devin/global_rules.md` (or `.windsurf/global_rules.md` when `.devin/` has none) to the instructions after a general rule, falls back to `.windsurfrules` for the instructions, merges `.devin/skills/` with `.windsurf/skills/`, and reads `.devin/mcp_config.json`. With Devin as the source, the `global_rules.md` and `.windsurfrules` it reads (`source_files()`) are never written by another target, deleted by `remove`/`migrate`, nor gitignored
- Orphan cleanup also covers conforme's old copies in the legacy locations, since Devin loads them next to `.devin/`: `.windsurf/rules/<file>.md` once the same file is generated in `.devin/rules/`, and a `.windsurf/skills/<name>/` folder holding nothing but its `SKILL.md` once the same skill is generated in `.devin/skills/`. Other legacy rules, and skill folders that bundle scripts or references, are the user's and stay (a rule an earlier sync wrote and the source has since dropped stays too)
- A `.conformerc.toml` or command line that still names `windsurf` (`source`, `only`, `exclude`, `--from`, `remove`, `migrate`) is an error naming the new id, so an `exclude = ["windsurf"]` is never silently ignored
- `.devin/mcp_config.json` is merged (`is_shared_file`): per-server OAuth fields survive, `disabled` is reset so a synced server is enabled, a file conforme cannot parse is left untouched, and `remove`/`migrate` keep it

## Notes

- The character limits (12,000 per rule file, 6,000 for global rules) are Cascade-only, so they no longer apply to Devin Local
- Rules: "Rule files in `.devin/rules/` and `.windsurf/rules/` are both loaded"; discovery is recursive since Devin CLI v3000.11.1 (2026-09-21)
- Manual-only skills are `triggers: [user]` (default `[user, model]`); conforme writes that, and reads a `triggers` list without `model` as manual. Devin documents no `disable-model-invocation`, so conforme does not write it here
- Skill `allowed-tools` takes Devin's own names (`read`, `edit`, `grep`, `glob`, `exec`, `write`, `mcp__server__tool`) and only skips permission prompts ("Tools that are not listed remain available"), so conforme does not copy another tool's list into it
- MCP: "The MCP config file location changed in v3000.3 … newer versions store them in dedicated files". conforme writes `transport: "http"` for remote servers (its normalized remote transport is streamable HTTP), `env` only on stdio servers, and `${env:VAR}` for environment references (read back as `${VAR}`)
- The Devin Local page still shows `.devin/config.json` for MCP; the MCP configuration page (newer) gives `.devin/mcp_config.json`, which conforme follows
- Devin Local also reads `CLAUDE.md`, `.cursor/rules/` and `AGENTS.md`; AGENTS.md at the root is always-on, and in a subdirectory it applies to `<dir>/**`
- Devin also loads skills from `.agents/skills/`, `.claude/skills/` and `.cursor/skills/`, so a skill can appear twice when Codex/Zed, Claude Code or Cursor are synced too
- `globs` is written as one comma-separated string, the historical Windsurf form, with brace groups expanded (`src/*.{ts,tsx}` → `src/*.ts, src/*.tsx`); a YAML list is also read. Whether the current agent splits a comma-separated string is not documented (unverified)
- Subagents (`.devin/agents/`, also `.agents/agents/`) are marked experimental upstream and are not generated yet (known gap)
- Hooks and workflows are Devin-specific and not synced
- The docs live at `docs.devin.ai` (the old `docs.windsurf.com/*` URLs redirect there); `cli.devin.ai/docs/*` redirects to `docs.devin.ai/cli/*`
