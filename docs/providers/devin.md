# Devin Desktop (formerly Windsurf)

> Cognition's AI IDE, formerly Windsurf. Source: `--from devin`

**Last verified online:** 2026-11-12, against Devin Desktop 3.12.43 and Devin CLI 3000.12.43 (https://docs.devin.ai/desktop/changelog, https://docs.devin.ai/cli/changelog/stable)

Windsurf was renamed Devin Desktop in v3.0.12 (2026-06-02). Since v3.6.21
(2026-07-29) new tabs defaulted to the **Devin Local** agent, and v3.9.19
(2026-09-08) removed Cascade, Windsurf's original agent: "Devin Local is now
the only agent available in Devin Desktop". Devin Local runs on the Devin CLI
harness, so the Devin CLI documentation is what describes the files read.

conforme's tool id was `windsurf` until 4.0.0 and is now `devin`.

## Config files

| Feature | Path | Format |
|---------|------|--------|
| Rules | `.devin/rules/*.md` (also loaded: legacy `.windsurf/rules/*.md`, root `.windsurfrules`) | YAML frontmatter: `trigger`, `description`, `globs` |
| Skills | `.devin/skills/<name>/SKILL.md` (legacy `.windsurf/skills/` is still read) | YAML frontmatter: `name`, `description`, `triggers`, `allowed-tools`, … |
| MCP | `.devin/mcp_config.json` (project; `.devin/mcp_config.local.json` for local secrets) | JSON: `{ "mcpServers": { ... } }`; no `type`; remote `url` + optional `transport: http\|sse` + `headers`; `${env:VAR}` references |
| Agents | `.devin/agents/<name>.md` or `<name>/AGENT.md` (also `.agents/agents/`) | YAML frontmatter: `name`, `description`, `model`, `allowed-tools`, `max-nesting` (experimental). **Not generated by conforme** |

## Activation modes

| Mode | Frontmatter |
|------|------------|
| Always | `trigger: always_on` |
| GlobMatch | `trigger: glob` + `globs: "**/*.ts, **/*.tsx"` |
| AgentDecision | `trigger: model_decision` + `description: "..."` (`trigger: agent` means the same and is read as such) |
| Manual | `trigger: manual` |

## conforme adapter

- File: `src/adapters/devin.rs`
- ID: `devin`
- Detection: `.devin/`, `.windsurf/`, or a root `.windsurfrules`
- Capabilities: activation_modes, skills, MCP
- No agents (`sync` warns that they are skipped)
- Writes `.devin/rules/`, `.devin/skills/` and `.devin/mcp_config.json`, also for a project that still has only `.windsurf/`
- `read()` merges `.devin/rules/` and `.windsurf/rules/` (both read recursively; on a name clash the `.devin/` copy wins), adds `.devin/global_rules.md` (or `.windsurf/global_rules.md` when `.devin/` has none) to the instructions after a general rule, then the root `.windsurfrules` (one of Devin's standard rule files, "loaded as always-on rules" alongside the others: https://docs.devin.ai/cli/extensibility/rules), merges `.devin/skills/` with `.windsurf/skills/`, and reads `.devin/mcp_config.json`. With Devin as the source, the `global_rules.md` and `.windsurfrules` it reads (`source_files()`) are never written by another target, deleted by `remove`/`migrate`, nor gitignored
- Orphan cleanup also covers conforme's old copies in the legacy locations, since Devin loads them next to `.devin/`: `.windsurf/rules/<file>.md` once the same file is generated in `.devin/rules/`, and a `.windsurf/skills/<name>/` folder holding nothing but its `SKILL.md` once the same skill is generated in `.devin/skills/`. Other legacy rules, and skill folders that bundle scripts or references, are the user's and stay (a rule an earlier sync wrote and the source has since dropped stays too)
- A `.conformerc.toml` or command line that still names `windsurf` (`source`, `only`, `exclude`, `--from`, `remove`, `migrate`) is an error naming the new id, so an `exclude = ["windsurf"]` is never silently ignored
- `.devin/mcp_config.json` is merged (`is_shared_file`): per-server OAuth fields survive, `disabled` is reset so a synced server is enabled, a file conforme cannot parse is left untouched, and `remove`/`migrate` keep it
- `type` is owned by conforme in `.devin/mcp_config.json` entries (Devin writes `transport`), so a stale hand-written `type` never contradicts a transport change
- Two rules of the same file name in `.devin/rules/` sub-directories are both read, for validation to report; a `general.md` in a sub-directory is an ordinary rule
- A `${VAR:-default}` loses its default (`${env:VAR}` has none) and an editor variable is not resolved: `sync` warns

## Notes

- Project hooks: not written. Devin CLI reads Claude Code's `.claude/settings.json` hooks by default (https://docs.devin.ai/cli/extensibility/hooks/overview), so with Claude Code in the project it already runs them; `sync` says so when the source has hooks (`hooks = true`)
- The character limits (12,000 per rule file, 6,000 for global rules) are Cascade-only, so they no longer apply to Devin Local
- Rules: "Rule files in `.devin/rules/` and `.windsurf/rules/` are both loaded"; discovery is recursive since Devin CLI v3000.11.1 (2026-09-21)
- Manual-only skills are `triggers: [user]` (default `[user, model]`); conforme writes that, and reads a `triggers` list without `model` as manual. Devin documents no `disable-model-invocation`, so conforme does not write it here
- Skill `allowed-tools` takes Devin's own names (`read`, `edit`, `grep`, `glob`, `exec`, `write`, `mcp__server__tool`) and only skips permission prompts ("Tools that are not listed remain available"), so conforme does not copy another tool's list into it
- MCP: "The MCP config file location changed in v3000.3 … newer versions store them in dedicated files". conforme writes `transport: "http"` for remote servers (its normalized remote transport is streamable HTTP), `env` only on stdio servers, and `${env:VAR}` for environment references (read back as `${VAR}`). Where `${env:VAR}` expands is documented only for the OAuth fields ("Like other OAuth fields, `oauthResource` supports `${env:VAR}` and `${file:/path}` expansion"); the legacy Cascade page that listed `command`, `args`, `env`, `serverUrl`, `url` and `headers` now redirects to the customizations page, which does not mention expansion. Devin's source is not public, so expansion in `env`/`headers` is unconfirmed
- A legacy SSE server is written as `url` + `transport: "sse"` with `headers`, Devin's own key for SSE, and read back as SSE (https://docs.devin.ai/cli/extensibility/mcp/configuration)
- Devin Desktop loads this project file too: since 3.9.19 "Devin Local is now the only agent available in Devin Desktop" (https://docs.devin.ai/desktop/changelog), and its customizations page names the project file: "`.devin/mcp_config.json`", shared "Yes (checked into version control)", beside `.devin/mcp_config.local.json` and `~/.config/devin/mcp_config.json` (https://docs.devin.ai/desktop/devin-local/customizations), that is `~/.config/devin/mcp_config.json`, `.devin/mcp_config.json` and `.devin/mcp_config.local.json` (https://docs.devin.ai/cli/reference/configuration/global-vs-local). The old global `~/.codeium/windsurf/mcp_config.json` is only a source Devin imports from (https://docs.devin.ai/cli/reference/configuration/read-config-from), so conforme does not write it
- Project MCP servers live in `.devin/mcp_config.json`: the CLI configuration reference says "Only `permissions`, `read_config_from`, and `hooks` are available in project configs. `mcpServers` can also be set at both levels, but lives in the dedicated `mcp_config.json` files" (https://docs.devin.ai/cli/reference/configuration/config-file) (the older Devin Local page still shows `config.json`)
- Devin also imports other tools' files (`.cursor/rules`, `.claude/skills`, `.github/skills`, …): with those targets synced too, the same rules and skills reach Devin twice. It imports MCP servers as well, from `.cursor/mcp.json`, `.mcp.json`, `.claude/settings.json`, `opencode.json` and `.zed/settings.json` (https://docs.devin.ai/cli/reference/configuration/read-config-from), so a synced server can reach Devin from several files. `read_config_from` in `.devin/config.json` turns an import off per tool
- Devin Local also reads `CLAUDE.md`, `.cursor/rules/`, `AGENTS.md`, `AGENT.md` and a personal `AGENTS.local.md` (https://docs.devin.ai/cli/extensibility/rules); AGENTS.md at the root is always-on, and in a subdirectory it applies to `<dir>/**`
- Devin also loads skills from `.agents/skills/` and `.kiro/skills/`, and "also reads skills that other tools keep in their own directories" "such as `.claude/skills/`, `.github/skills/`, `.codex/skills/`" (https://docs.devin.ai/cli/extensibility/skills/overview), so a skill can appear twice when Codex/Zed, Kiro, Claude Code or Copilot are synced too; `.cursor/skills/` is not among them
- `globs` is written as one comma-separated string, the historical Windsurf form, with brace groups expanded (`src/*.{ts,tsx}` → `src/*.ts, src/*.tsx`); a YAML list is also read. Whether the current agent splits a comma-separated string is not documented (unverified)
- Subagents (`.devin/agents/`, also `.agents/agents/`) are marked experimental upstream and are not generated yet (known gap)
- Hooks and workflows are Devin-specific and not synced
- The docs live at `docs.devin.ai` (the old `docs.windsurf.com/*` URLs redirect there); `cli.devin.ai/docs/*` redirects to `docs.devin.ai/cli/*`
