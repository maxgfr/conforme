## Config files

| Feature | Path | Format |
|---------|------|--------|
| Instructions | `AGENTS.md` (native), then `CLAUDE.md` | Markdown |
| Local overlay | `AGENTS.local.md`, then `CLAUDE.local.md` | Markdown (not generated by conforme) |
| Skills | `.dsh/skills/<name>/SKILL.md` | YAML frontmatter: `name`, `description` |
| Shared skills | `.agents/skills/<name>/SKILL.md` | Same format, lower discovery rank |
| MCP | `$DSH_HOME/cordis.patch.yml` (user-level) | YAML plugin entries — **not project-scoped** |

## Activation modes

None. The harness loads every discovered instruction file for the session's
directory chain, so all content is always-on.

## Instruction discovery

`@deepseek-ai/dsh-agent-instructions` walks up from the session cwd to the
project root (identified by `projectRootMarkers`, default `['.git']`) and, in
each directory, loads every existing candidate:

- `instructionFileCandidates` default: `['AGENTS.md', 'CLAUDE.md']`
- `localInstructionFileCandidates` default: `['AGENTS.local.md', 'CLAUDE.local.md']`

A fixed user-global `AGENTS.md` also lives in the harness home (`$DSH_HOME`,
default `~/.dsh`). Per-directory duplicates with identical trimmed content
collapse to the earliest candidate.

## Skills discovery

The filesystem provider scans roots in rank order:

| Rank | Source | Path |
|---|---|---|
| 100 | `project-dsh` | `<projectRoot>/.dsh/skills` |
| 200 | `project-agents` | `<projectRoot>/.agents/skills` |
| 300 | `custom` | `Config.customSkillDirs` |
| 400 | `user-dsh` | `<dshHome>/skills` |
| 500 | `user-agents` | `<agentsHome>/skills` (`$DSH_AGENTS_HOME` or `~/.agents`) |
| 600 | `bundled` | `Config.bundledSkillDir` when configured |

Both `<name>/SKILL.md` bundles and flat `<name>.md` files are accepted;
nested discovery is deliberately excluded. Frontmatter is an open YAML object;
the provider interprets required `name` and `description`, plus optional
`whenToUse`, `metadata`, `disable-model-invocation`, and `user-invocable`.
Names must be kebab-case. A camel-case spelling of the two invocation keys or a
non-boolean invocation value drops the whole skill with a warning.

## MCP

MCP servers are one `@deepseek-ai/dsh-mcp-client` plugin entry per server in
`cordis.yml` / the user `cordis.patch.yml` under `$DSH_HOME` (or a profile
directory), for example:

```yaml
- id: mcp-github
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: github
    transport: stdio
    command: npx
    args: ['-y', '@modelcontextprotocol/server-github']
```

`transport` is `stdio` (`command`, `args`, `env`, `cwd`) or `streamable-http`
(`url`, `headers`). Tools are exposed as `mcp__<serverName>__<rawName>`.
Because this configuration is user-level and not project-scoped, conforme does
**not** generate an MCP file for this tool.

## conforme adapter

- File: `src/adapters/deepseek.rs`
- ID: `deepseek`
- Detection: `.dsh/` directory exists
- Capabilities: skills only
- No activation modes, no agents, no project-scoped MCP
- `generate()` writes `.dsh/skills/<name>/SKILL.md` (AGENTS.md is read natively)
- `read()` round-trips AGENTS.md (falling back to CLAUDE.md) plus skills from
  `.dsh/skills/`, falling back to the shared `.agents/skills/` root
- Managed directory for orphan cleanup: `.dsh/skills`

## Notes

- Developer preview — the harness README warns that APIs will change
- Everything is a Cordis plugin: models, tools, skills, sessions, sandboxes,
  storage, loops, scheduling, and the UI
- Run locally with `npx @deepseek-ai/dsh web` (Node.js `^22.19` or `>=24`),
  which serves the Web UI on `http://127.0.0.1:3080`
- Subagents exist at runtime (the `subagent` packages) but are plugin-composed,
  not user-defined markdown files, so conforme does not sync agents here
- The project `.dsh/` directory is used for skills only; settings and
  credentials live in the harness home (`settings.yaml`, `.credentials.yaml`)
